[1] STARTUP SEQUENCE
1. Connect Phone A -> Laptop A (via USB Tethering).
2. Connect RJ45 LAN cable (or Gigabit Switch) to all registration laptops.
3. Turn ON Mobile Hotspot on Laptop A.
4. Connect all scanner phones to Laptop A's Mobile Hotspot.
5. Launch server_hub.py -> Click "▶ Start Engine".
6. Start Cloudflare Gateway/Tunnel (if internet is active) & share the public link.

[3] IF INTERNET STOPS (OFFLINE MODE)
- Local Hotspot & LAN : WORKING NORMALLY.
- Registration Desks  : Continue using http://<IP>:5000.
- Gate Scanners       : Continue using https://<IP>:5001.
- Cloudflare Remote   : DOWN (Remote staff cannot connect until the internet returns).
- FIREWALL RULE: To ensure mobile scanners on your local Wi-Fi can reach the Waitress engine (Port 5000) and HTTPS Cheroot engine (Port 5001), run this exact command in PowerShell (Admin):
  > New-NetFirewallRule -DisplayName "EventHub Ports" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5000,5001

[4] HARDWARE & NETWORK LAYOUT
- Laptop A (Central) : Runs server_hub.py. Acts as the brain; connects to everything below.
- Phone A (USB)      : Acts as the internet backbone AND the Master Gate Scanner.
- RJ45 LAN Laptops   : Used strictly for register.py / Kiosk data entry.
- Hotspot Phones     : Up to 8 Android/iOS devices used strictly for check_in.py / QR Scanning.

[5] FIREWALL & NETWORK PROFILE (CRITICAL)
- Allow Windows Firewall ports: 5000 (HTTP), 5001 (HTTPS), and 3306 (Only for remote MySQL admin access).
- IMPORTANT: Ensure your active Windows network profile is set to "Private" (not "Public"). Windows automatically blocks local LAN traffic on "Public" networks.
- Pause or add exceptions to third-party antiviruses (McAfee, Norton, Avast, etc.). Their built-in firewalls often override Windows Firewall and silently block connections.

[6] WINDOWS SERVER OPTIMIZATION (PREVENT SLEEP DROPS)
- Settings > System > Power & sleep: Set "Screen" and "Sleep" to "Never".
- Device Manager > Network Adapters > Right-click your Wi-Fi/Ethernet adapters > Properties > Power Management: UNCHECK "Allow the computer to turn off this device to save power".

[7] FIX: DEVICES CANNOT LOAD THE IP ADDRESS
- Step 1: Verify Laptop A's IP address hasn't changed. Re-run `ipconfig` in Command Prompt to confirm the IPv4 Address.
- Step 2: Ensure the client device is actually connected to the correct Wi-Fi Hotspot or LAN switch.
- Step 3: Turn OFF any active VPNs on both Laptop A and the client mobile devices (VPNs scramble local IP routing and prevent LAN discovery).

[8] FIX: CLOUDFLARE WON'T OPEN
Change Laptop A's DNS settings to:
- Preferred DNS : 1.1.1.1
- Alternate DNS : 1.0.0.1

[9] FIX: NETWORK SHOWS OFFLINE / GLITCHY
Run Command Prompt as Administrator and execute these commands one by one:
  > ipconfig /flushdns
  > ipconfig /release
  > ipconfig /renew
  > netsh winsock reset
*IMPORTANT: Restart the PC after running the winsock reset command.*
